# AIUX · 七章交互说明

交互说明按页写、逐页自包含。每页都有完整七章，但全局类章节只写「对本报的影响面」。

## 0. 先选端

一个任务只选一个端，交互说明的口径跟着端走。

| 端 | profile | 组件库 | spec 里的 `mcp.framework` |
|---|---|---|---|
| 桌面端 | `vue-next` | `tdesign-vue-next@1.20.10` | `vue-next` |
| 移动端 | `mobile-vue` | `tdesign-mobile-vue@1.17.1` | `mobile-vue` |

移动端要额外写：手势（点击/长按/滑动/下拉刷新）、触摸目标 ≥ 44px、安全区、键盘避让、单手可达。桌面端要写：hover、快捷键、右键/双击（如果有）。

## 1. 四步链路

1. **唤起**：`/aiux`。确认这次做哪几页；检查 MCP；加载 TDesign 技能。
2. **铺预览**：复制 vendor，生成空壳页；双击能开、右下按钮能展开抽屉。
3. **逐页循环**：查 MCP → 边聊边写本页七章 → 生成本页 HTML → 点击条目验证滚动与高亮。
4. **收口**：全部页面跑校验；0 违规后导出逐页 md 与前端开发自检清单，生成前端自检清单，再起 `aiux-serve` 预览服务，验证 HTTP 后给出 Local 与 Network 地址。

一页没通过校验，不开始下一页。

## 2. 七章大纲

| 章节 | 写什么 | 来源规则 |
|---|---|---|
| 1 用户与权限 | 角色定义、权限矩阵、角色间行为差异 | 只写用户提到或已存在的角色；未提及写「未提供」 |
| 2 信息架构 | 本页在功能地图中的位置、页面层级、导航与跳转关系 | 只写实际存在的跳转，不推测 |
| 3 页面/模块详述 | 见下方 6 个子节，核心 | 逐页写，本页专属 |
| 3.1 页面目标与入口 | 这一页解决什么，从哪进来 | 从对话归纳，一句话 |
| 3.2 布局与元素清单 | 分区与元素，每个元素标出 TDesign 组件名 | 组件名必须来自 MCP 白名单 |
| 3.3 交互流程 | 主流程 + 异常流程 | 每条带 `id` 与锚点 |
| 3.4 状态设计 | 默认/加载/空/错误/无权限/超限 | 六态齐全，不涉及的写原因，不能留白 |
| 3.5 字段与校验 | 必填、格式、长度、错误提示文案 | 只记对话里说过的；没说不许发明，进待确认 |
| 3.6 按钮与操作反馈 | hover/点击/禁用/二次确认/Toast | 逐按钮写，含禁用条件 |
| 4 全局交互规范 | 加载与反馈时长、动效、快捷键、返回与中断、刷新与缓存 | 只写影响本页的部分；token 覆写也记这里 |
| 5 边界与异常 | 网络异常、并发操作、数据为空、超时、重复提交 | 有结论才写，没有进待确认 |
| 6 数据与埋点 | 关键事件、上报字段、成功/失败判定 | 只记用户给的事件名；方案由产品与数据侧定 |
| 7 国际化与适配 | 多语言、分辨率/响应式、无障碍 | 不涉及的写「不涉及」并说明原因 |

### 3.5 最容易越界

插件只记录你明确说过的校验规则和文案。你没说的，写进 `openQuestions`，标明属于产品还是前端，不自行补全。不要写「应该限制 50 字」这种推测；要么是用户说的，要么进待确认。

### 3.4 六态

六个 key 必须都存在且非空：`default` / `loading` / `empty` / `error` / `noPermission` / `overLimit`。

不涉及也要写原因，例如：

```json
"noPermission": "不涉及：本页只有运营可见，不存在角色差异。"
```

不允许空字符串、`待填写`、`英文待办占位词`。

## 3. 三条铁律

1. **只写对话里出现的内容**。不推断、不补全、不「合理设计」。
2. **空缺必须显式标记**。`未提供` / `不涉及：原因` / `转产品确认`，三选一，禁止留白。
3. **业务规则与接口不进正文**。全部进 `openQuestions`，标明转给谁。

校验脚本会把 `待填写` / `待生成` / `空壳页` / `英文待办占位词` / `TBD` 判为占位内容，直接报错。

## 4. 逐页自包含

- 交互说明按页写，不合并成一份大文档。
- 每页文档都含完整七章，但全局类章节只写「对本页的影响面」：
  - 用户与权限 → 只看本页的角色差异
  - 信息架构 → 只写本页的位置、入口、去向
  - 全局交互规范 → 只写与本页有关的加载、动效、快捷键、返回
- 跨页的全局视图看目录本身，正文只留在各页。

## 5. 锚点与高亮

- 每条交互带 `id`（`I-01`）与 `anchor`（对应元素上的 `data-aiux` 值）。
- `anchor` 只写值，不带 `#`、类名或选择器。
- 页面元素写 `data-aiux="list-area"`。
- 抽屉里点击条目：平滑滚动到元素，加 1.5 秒品牌色描边。
- 找不到对应元素时，抽屉内就地提示「未绑定元素」，并计入校验失败。
- `id` 在全页唯一；多个条目可以指向同一个 anchor。
- 页面上的 `data-aiux` 必须真实存在，不能只写在 JSON 里。

## 7. 各章写法

### 1 用户与权限

- `roles`：只写对话里出现或已存在的角色，包含名称和一句话说明。
- `matrix`：角色 × 操作 × 是否允许；没有就空数组。
- `roleDiffs`：本页的角色差异；没有写 `["未提供"]`。

### 2 信息架构

- `position`：本页在功能地图中的位置；不知道写 `未提供`。
- `entries` / `exits`：只写实际存在的入口和去向，不推测。

### 3.1 页面目标与入口

一句话：这一页解决什么、从哪进来。不要写成长段落。

### 3.2 布局与元素清单

- 每个元素写名称 + TDesign 组件名。
- 组件名来自 MCP 白名单；自造组件必须登记 `gaps`。
- 有锚点的元素写 `anchor`，并在页面上加 `data-aiux`。

### 3.3 交互流程

- 主流程和异常流程分开。
- 每条：`id`、`text`、`anchor`。
- 一条只写一个可验证的行为，不要写「体验流畅」这种不可验证描述。
- 移动端写清手势：点击、长按、左滑、下拉刷新、滚动加载；不要写只有 hover 才能触发的交互。
- 桌面端写清 hover、快捷键、右键/双击（如果有）。

### 3.4 状态设计

逐页写六态。加载态写清是局部还是整页；空态写清文案和下一步入口；错误态写清是否保留已加载数据；无权限写清隐藏什么；超限写清阈值和提示。

### 3.5 字段与校验

- `name`：字段名。
- `rule`：必填、格式、长度等。
- `message`：错误提示文案。
- `status`：`已确认` / `转产品确认` / `转前端确认`。

只写对话里说过的规则和文案。没说的不要编。

### 3.6 按钮与操作反馈

逐按钮写：

- hover / 按压有没有变化
- 点击后发生什么
- 什么时候禁用
- 是否需要二次确认
- 成功/失败是 Toast、Message 还是页面内反馈
- 移动端写清触摸目标是否 ≥ 44px、是否有按压态、是否会被安全区或键盘遮挡

### 4 全局交互规范

只写影响本页的部分。`tokenOverrides` 逐条登记根容器覆写的 token。

### 5 边界与异常

有结论才写。没有结论的进 `openQuestions`，不要写「待定」。

### 6 数据与埋点

只记用户给过的事件名、触发时机、上报字段。具体方案由产品与数据侧定。

### 7 国际化与适配

多语言、分辨率/响应式、无障碍。不涉及的写 `不涉及：原因`。

- 桌面端写清浏览器与分辨率，例如 `Chrome / Safari / Edge × 1440 / 1920`。
- 移动端写清机型宽度与高度，例如 `375 / 390 / 414 × 667 / 812 / 844`，并写触摸目标 ≥ 44px、安全区、系统字体放大。
- 无障碍写清键盘/读屏/焦点顺序；移动端补充点击热区和手势替代路径。

## 8. 页面完成检查

- [ ] `summary` 3–5 句，能独立说明这一页
- [ ] 七章齐全，没有空字符串、`待填写`、`英文待办占位词`
- [ ] 主流程/异常流程每条都有 id、text、anchor
- [ ] 每个 anchor 都能在页面找到 `data-aiux`
- [ ] 六态齐全，不涉及的写了原因
- [ ] 3.5 只写对话里说过的规则与文案
- [ ] `mcp.framework` 与任务 profile 一致（`vue-next` / `mobile-vue`）
- [ ] `mcp.checkedComponents` 覆盖实际组件
- [ ] `openQuestions` 标明 reason 和 owner
- [ ] 移动端检查了手势、触摸目标 ≥ 44px、安全区、键盘遮挡
- [ ] 没有编辑 `.aiux/docs/*.md` 或 `自检清单.md`；它们是生成物
- [ ] 已运行 `aiux-serve`，HTTP 返回 `200` / `304`
- [ ] 最终回复同时给出 Local 与 Network 可点击链接，端口写实际端口
- [ ] 启动失败时贴了真实日志，没有编造地址
- [ ] 评审结束已停止服务，或写明重启命令
